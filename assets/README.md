# HTML 템플릿 — 채우기 지침

이 폴더의 세 파일은 **검증된 완성 구현체**다. CSS와 JS는 손대지 않는다.
`{{자리표시자}}`만 바꿔 프로젝트 폴더에 저장한다.

**왜 템플릿인가.** 이전에는 규격이 스킬 안에 산문으로만 있었고, 코치가 매 세션 HTML을
처음부터 손으로 짰다(한 본문에 1,904줄). 그 과정에서 아래 「재발 방지 목록」의 버그가
실제로 발생했고, 설교자가 화면에서 발견했다. 산문 경고는 재발을 막지 못한다 — 작동하는
코드만이 막는다.

| 파일 | 쓰는 단계 | 용도 |
|---|---|---|
| `text-viewer.html` | 1단계 | 5역본 비교 뷰어 (구문 배열 + 절별 비교 + 낭독) |
| `tts-reader.html` | 2단계 | 정독용 TTS + 걸리는 줄 밑줄 수집 |
| `prompter.html` | 3·7·8·9·10단계 | 강단 프롬프터 (낱말 편집 + 낭독 + 점검 제출) |

---

## 공통 규칙

1. **CSS·JS는 한 글자도 바꾸지 않는다.** 바꿔야 할 이유가 생기면 그건 템플릿을 고칠 일이지
   사본을 고칠 일이 아니다. 템플릿을 고치고 이 문서의 버전 줄을 올린다.
2. **성경 본문은 설교자가 준 것만 넣는다.** 코치가 생성·재현하지 않는다(특히 새한글 2021).
3. **설교자 원문은 무수정.** 맞춤법 오타만 교정하고, 성경 인용은 오타도 손대지 않는다.
4. 채운 뒤 **반드시 아래 「검증 절차」를 수행한다.** 빠뜨리면 조용히 깨진 파일을 건네게 된다.

## 1. text-viewer.html (1단계)

| 자리표시자 | 내용 |
|---|---|
| `{{TITLE}}` | 큰 제목 |
| `{{SUBTITLE}}` | 교회·예배·날짜·단계 한 줄 |
| `{{REF}}` | 본문 범위 + 앞뒤 문맥 |
| `{{DATA}}` | 아래 스키마 |
| `{{ESV_DATA}}` | 아래 스키마 |
| `{{FOOTER}}` | 구문 배열 설명 + 역본 저작권 |

### {{DATA}} 스키마 — **섹션 배열이지 절 배열이 아니다**

```js
  {
    id:"prev", tag:"앞장", ref:"누가복음 18:35-43",
    title:"여리고 가까이에서 시각장애인을 고쳐 주시다",
    main:false,        // 확정 단위면 true (테두리 강조)
    open:false,        // 처음부터 펼칠지
    v:{
      35:{ "새한글":`…`, "개역개정":`…`, "새번역":`…`, "공동번역":`…` },
      36:{ "새한글":`…`, "개역개정":`…`, "새번역":`…`, "공동번역":`…` }
    }
  },
  { id:"main", tag:"본문", … main:true, open:true, v:{ … } },
```

- 절 번호는 **숫자 키**다. 문자열 키로 넣으면 `Object.keys().map(Number)`가 `NaN`이 되어
  **오류 없이 빈 화면**이 나온다. 이 함정에 실제로 걸린 적이 있다.
- 본문은 **백틱**으로 감싼다(따옴표·줄바꿈 안전).
- ESV는 `{{DATA}}`에 넣지 않는다 — 별도 `{{ESV_DATA}}`.

### {{ESV_DATA}} 스키마 — 섹션 id로 키를 맞춘다

```js
  prev:{ 35:`As he drew near to Jericho…`, 36:`…` },
  main:{ 1:`He entered Jericho and was passing through.`, 2:`…` }
```

`{{DATA}}`의 `id`와 키가 어긋나면 그 섹션의 ESV만 조용히 빈칸이 된다.

## 2. tts-reader.html (2단계)

| 자리표시자 | 내용 |
|---|---|
| `{{TITLE}}` / `{{REF}}` | 제목 / 본문 범위 |
| `{{TEXT_DATA}}` | 아래 스키마 |
| `{{STORAGE_KEY}}` | `tnt2:{본문}` (예: `tnt2:눅19,1-10`) — 뒤에 역본명이 붙는다 |
| `{{SUBMIT_HEADING}}` | 제출 상자 제목 |

```js
  "개역개정":{ 1:`예수께서 여리고로 들어가 지나가시더라`, 2:`…` },
  "새한글":{   1:`…`, 2:`…` }
```

역본 버튼은 개역개정·새한글 둘이다. 둘 다 채운다 — 한쪽이 없으면 그 역본에서 빈 화면이 된다.

## 3. prompter.html (3·7·8·9·10단계)

| 자리표시자 | 내용 |
|---|---|
| `{{TITLE}}` / `{{SUBTITLE}}` / `{{REF}}` | 머리말 |
| `{{ANCHOR_LABEL}}` / `{{ANCHOR_TEXT}}` / `{{ANCHOR_NOTE}}` | 앵커 구절 카드. 4단계 전이면 전환점 절, 이후면 중심 메시지 |
| `{{LEGEND}}` | 이 파일의 용도·조작법. **단계마다 다르게 쓴다** |
| `{{BLOCKS}}` | 아래 스키마 |
| `{{SUBMIT_HEADING}}` | 제출 상자 제목 (예: `3단계 낭독 점검 제출`) |
| `{{FOOTER}}` | 저작권·무수정 고지·단축키 |
| `{{STORAGE_KEY}}` | `tnt{단계}:프롬프터:기준선:{본문}` |
| `{{BASELINE}}` | **재생성할 때마다 반드시 올린다** (아래 재발 방지 ③) |

### {{BLOCKS}} 스키마

```html
  <section class="sermon-block" id="b0">
    <div class="block-title"><span class="no">장면 1</span>
      <span class="nm">삭개오가 나무에 오르다</span>
      <span class="vs">눅 19:2-4 · 등장</span>
      <button class="btn-read" data-b="b0">▶ 읽기</button></div>
    <div class="block-body">
      <p>첫째 호흡입니다.<br>
      둘째 호흡입니다.</p>
      <blockquote>본문 인용은 blockquote</blockquote>
    </div>
  </section>
```

- `id`는 `b0`부터 순번, `data-b`와 반드시 일치시킨다(불일치 시 그 장면 읽기 버튼만 죽는다).
- **`.no` 라벨은 단계에 따라 다르다.** 3단계는 `도입`·`장면 N`(모델 미확정),
  7단계 이후는 모델 칸(`D1`~`D6` / `P1`~`P5` / `01`~`03`).
- **장면 제목(`.nm`)은 설교자가 붙인다.** 미정이면 `(제목 미정 — 설교자 명명)`.
- **`<br>` = 호흡 한 단위.** 한 줄에 한 호흡, 접속·전환에서 끊는다. 낱말은 바꾸지 않는다.
- 아직 없는 장치는 넣지 않는다 — 3단계에 전달 표시(10단계)·`.ai-mark`(9단계)를 넣지 않는다.
- 코치가 닫지 못한 수정 요청은 해당 문단 뒤 `.no-tts` 상자로 단다(화면엔 보이고 낭독엔 제외).

## ★ 재발 방지 목록 — 넷 다 실제로 발생했다

이 항목들은 템플릿 안에 **이미 고쳐져 있다.** CSS·JS를 손대면 되살아난다.

| # | 증상 | 원인 | 템플릿의 방어 |
|---|---|---|---|
| ① | 절 번호가 **화면에서 사라짐** | `text-indent`는 상속된다. 음수 들여쓰기를 준 문단 안의 인라인블록 `.vn`이 자기 글자에 그 값을 다시 적용 | `.vn`에 `text-indent:0` |
| ② | 낱말 편집 후 **호흡 줄나눔 소실** | 편집 삽입이 `<br>`을 텍스트로 평탄화 | Enter→`<br>` 변환 + `↵ 호흡 나누기` 버튼 |
| ③ | 옛 편집이 **재생성 원고를 덮어씀** | `localStorage`가 이전 본문 기준으로 복원 | 기준선 스탬프 — `BASE`가 바뀌면 옛 편집 폐기 |
| ④ | 낭독 첫 문장이 **화면 밖** | 고정 바 높이를 계산에 넣지 않음 | `block:'start'` + 바 높이 실측 |

①은 특히 위험하다. 당시 `getBoundingClientRect()`로 **박스**를 재어 "통과"로 보고했으나
화면엔 아무것도 없었고 설교자가 발견했다. 박스는 글자가 없어도 크기를 갖는다.

## 검증 절차 — 채운 뒤 반드시 한다

1. **자리표시자 잔존 검사** — `grep -o '{{[A-Z_]*}}' 파일` 결과가 비어야 한다.
2. **브라우저로 연다.** 파일이 열리는 것과 내용이 그려지는 것은 다르다.
   본문이 비었으면 십중팔구 데이터 스키마 오류다(위 `NaN` 함정).
3. **절 번호는 글리프로 잰다** — 박스가 아니라 글자다.
   ```js
   [...document.querySelectorAll('.vn')].map(el=>{
     const r=document.createRange(); r.selectNodeContents(el);
     const b=r.getBoundingClientRect();
     return {글자:el.textContent, 폭:b.width, 높이:b.height, 좌:b.left};
   })
   ```
   폭·높이가 0이거나 `left`가 음수면 **보이지 않는 것이다.**
4. **스크린샷을 찍어 눈으로 본다.** 위 셋을 다 통과해도 이걸 건너뛰지 않는다.

---

## 설교자에게 건넬 때

프롬퍼터의 편집·표시는 **브라우저 안에만** 있다. 설교자가 「수정 완료」·「낭독 점검 완료」로
제출한 내용을 코치가 받아 **원본 `.md`에 반영해야** 다음 단계로 넘어간다. 반영할 때도
설교자가 입력한 문장 그대로 옮기고 코치가 다듬지 않는다.
